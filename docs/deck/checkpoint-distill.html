## Order the guard before the cache read
The guard is what bounds the key space, so
reading first admits an unbounded key and
evicts live entries once traffic rises.
Widening the key was tried first. It reads
as the obvious fix and holds under test,
then storms on invalidation under real load.
→ the next session reads this before it writes a line
Nobody tries the cache key again.
